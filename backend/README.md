# KrishiMarg Backend (Java Spring Boot)

This is the core backend orchestrator for the KrishiMarg platform. It handles the REST APIs for the Farmer, Buyer, and Driver portals, interfaces with the PostgreSQL/PostGIS database, and acts as the central data hub.

## 🚀 Tech Stack
- **Framework**: Spring Boot / Java 17
- **Database**: PostgreSQL
- **Spatial Extension**: PostGIS (for geospatial radius searches)
- **ORM**: Hibernate Spatial / Spring Data JPA
- **Build Tool**: Maven

---

## 🛠️ Setup & Installation

### 1. Database Setup
Ensure you have PostgreSQL installed with the PostGIS extension. Run the following commands in `psql` or pgAdmin:

```sql
DROP DATABASE IF EXISTS krishimarg;
CREATE DATABASE krishimarg;
\c krishimarg
CREATE EXTENSION IF NOT EXISTS postgis;
```

Run the initialization script to create tables and dummy data:
```bash
psql -U postgres -d krishimarg -f src/main/resources/db/init.sql
```

### 2. Configure Credentials
Update the `src/main/resources/application.properties` file with your local PostgreSQL password:
```properties
spring.datasource.password=YourPasswordHere
```

### 3. Run the Application
Start the server using Maven from the `backend` folder:
```powershell
.\mvnw.cmd spring-boot:run
```
The backend will start on `http://localhost:8080`.

## 📂 Architecture & Directory Structure

```text
backend/src/main/java/com/krishimarg/backend/
├── controllers/          # API Endpoints (FarmerController, BuyerController, LogisticsController)
├── models/               # JPA Entities mapping exactly to the database schema
└── repositories/         # Spring Data JPA interfaces (includes PostGIS ST_DWithin spatial queries)
```

### 1. Entities (`models/`)
- `User.java`: Handles Farmers, Buyers, and Drivers.
- `ProduceLot.java`: Represents a farmer's crop listing. Uses `org.locationtech.jts.geom.Point` to natively store PostGIS SRID 4326 coordinates.
- `Order.java`: Represents a buyer's purchase. Uses `@JdbcTypeCode(SqlTypes.JSON)` to map a PostgreSQL `JSONB` array of `lot_ids`.
- `DeliveryRoute.java`: Stores the optimized route generated by the Python OR-Tools engine as `JSONB`.

### 2. Repositories (`repositories/`)
The standout repository is `ProduceLotRepository.java`. It utilizes a raw PostGIS spatial query to enable the buyer's localized search:
```java
@Query(value = "SELECT * FROM produce_lots p WHERE p.status = 'AVAILABLE' AND p.crop_name = :cropName AND ST_DWithin(p.farm_location::geography, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)::geography, :radiusMeters)", nativeQuery = true)
```
This efficiently draws a radius around the buyer's GPS coordinates and only returns produce inside that zone.

### 3. Controllers (`controllers/`)
- **FarmerController**: `GET /api/v1/farmer/insights` (Market bounds & ML Mock), `POST /api/v1/produce` (Listing).
- **BuyerController**: `GET /api/v1/buyer/search` (PostGIS radius search), `POST /api/v1/orders` (Checkout & Mock Payment).
- **LogisticsController**: `GET /api/v1/driver/routes`, `POST /api/v1/driver/routes/{id}/accept`, `POST /api/v1/driver/routes/{id}/complete`.
